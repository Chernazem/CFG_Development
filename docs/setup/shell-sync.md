# Актуальность оболочки CFG_Development

Источник флоу, skills, скриптов и правил — `origin/main` репозитория `CFG_Development` в корне workspace. Ноутбук и `TB-PC` подхватывают его отдельно: у каждой машины свой клон и своя метка.

Между ноутбуком и `TB-PC` оболочку передаёт этот git. Яндекс.Диск для правил, skills и скриптов не использовать (`docs/setup/yandex-disk.md`).

## Когда проверять

1. В старте каждой продуктовой задачи, на той машине, где агент начинает работу, и ещё раз на `TB-PC` до первой правки кода.
2. Повторно, если метка `.local-ci/cfg-development-sync.txt` старше 24 часов. Поле `checked_at_utc` — время UTC последней успешной проверки.

Метка локальная, в git не входит.

## Команда

Из корня workspace:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File "tools\scripts\update-cfg-development-shell.ps1"
```

На `TB-PC` тот же файл с `-WorkspaceRoot "D:\Dev Projects\TB"`.

Скрипт делает `git fetch origin main` и, если локальный `main` строго позади и в отслеживаемых файлах нет своих правок, `git pull --ff-only`. Продуктовые `repos/*` не трогает.

## Коды выхода

| Код | Смысл | Действие агента |
|-----|--------|-----------------|
| 0 | Локальный `main` не отстаёт от `origin/main`, метка обновлена | Продолжать задачу |
| 2 | На `origin/main` есть новые коммиты, а fast-forward закрыт своими коммитами или правками отслеживаемых файлов | Остановиться, показать `ahead`/`behind` и список правок. Задачу на старых правилах не начинать и не продолжать |
| 1 | `fetch` или git не выполнились | Остановиться и показать ошибку. Сеть и `origin` проверить до старта задачи |

После кода 0 следующий шаг читает уже файлы с диска. Отдельным перезапуском чата правила не «догружаются».
