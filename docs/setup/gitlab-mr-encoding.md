# GitLab MR и кодировка

При создании или обновлении Merge Request из automation, CLI или agent-процесса заголовок и описание с кириллицей готовить в UTF-8 JSON-файле без BOM и отправлять через `curl.exe --data-binary` с `Content-Type: application/json; charset=utf-8`.

Не передавай русский текст напрямую в аргументах PowerShell:

- `Invoke-RestMethod`;
- `-Title "..."`;
- here-string в команде запуска;
- другой inline-текст, который PowerShell может перекодировать.

После каждого создания или обновления MR обязательно перечитать MR через GitLab API или страницу GitLab и проверить, что `title` и `description` совпадают с исходным UTF-8 текстом.

Успешный HTTP-ответ не считается достаточной проверкой.

В заголовке и описании не должно быть:

- символов замены `�`;
- mojibake-фрагментов вроде `Ð` или `Ñ`;
- неожиданных `?` вместо кириллицы.

Если кодировка поехала:

1. Повторить обновление из UTF-8 JSON-файла без BOM через `curl.exe --data-binary`.
2. Снова перечитать MR.
3. Только после успешной проверки сообщать пользователю ссылку или статус.

В финальном статусе явно отмечать, что кодировка MR проверена.
