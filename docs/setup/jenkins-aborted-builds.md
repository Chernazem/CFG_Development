# Jenkins: три ABORTED подряд

## Правило

Если для одного MR (job `MR-<iid>` / pipeline ветки) **три завершённые сборки подряд** закончились **`ABORTED`**:

1. **Не** перезапускать сборку (Rebuild / Replay / empty commit / push «для ретрая»).
2. Остановить Jenkins heartbeat / `/loop`.
3. Зафиксировать в описании MR и в чате: номера трёх сборок, время, stage на котором abort.
4. **Ждать явной команды** пользователя или PM («можно ретраить» / «инфра починена»).

Это правило действует на ноутбуке PM и на worker `TB-PC` одинаково (см. `.cursor/rules/jenkins-mr-monitor.mdc`, critical-flow п.11).

## Зачем

Серия `ABORTED` почти всегда инфраструктура: таймаут агента, очередь, VPN/диск, убитый executor — не дефект кода задачи. Дальнейшие ретраи только забивают Jenkins.

## Что не считается

- Чередование `ABORTED` с `FAILURE`/`UNSTABLE`/`SUCCESS` — правило «три подряд» не срабатывает; разбирать по обычному critical-flow.
- Один или два `ABORTED` — можно один осознанный ретрай после разбора, затем снова считать серию.
- `FAILURE` из‑за Sonar/unit — чинить код/QG, не путать с abort-стопом.

## После команды «можно ретраить»

Счётчик серии сбрасывается. Новый push по фиксу кода — обычный цикл мониторинга.
