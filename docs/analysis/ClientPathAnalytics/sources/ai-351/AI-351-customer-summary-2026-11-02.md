# Решения по клиентской воронке — AI-351

02.11.2026 согласованы правила первой версии семантического слоя.

- **Результат попытки:** выбираем договор с первой фактической выдачей.
  Если выдач нет — последний заключённый договор; если договоров нет —
  заявку с последним одобрением, затем последнюю созданную заявку.
  Все остальные документы сохраняются. Одобрение учитывается как достигнутый
  этап; последующая отмена или отказ видны отдельно.
- **Окно выдачи:** день договора и следующий календарный день, по московскому
  времени. Выдача D2+ сохраняется отдельно. Договор не меняем ради попадания
  в D0–D1.
- **Путь клиента:** при договоре идём по цепочке договор → заявка → предзаявка.
  Без договора используем выбранную заявку, а если заявок нет — последнюю
  предзаявку. При недостатке подтверждений путь остаётся неопределённым.
  Факт запуска МПР учитывается отдельно от итогового пути.
- **Объединение обращений:** внутри дня до выдачи; между днями — по ID.
  D7 отменён. При ID-связях с разными прежними попытками их не объединяем;
  обращения без ID образуют отдельную дневную попытку. Новое обращение
  после выдачи начинает новую попытку.
- **Атрибуция:** канал, тип клиента, продукт и подразделение — по входу.
  Неизвестный продукт входа не подменяем продуктом договора. Контекст
  результата сохраняем отдельно.
- **Оргструктура:** tribe, squad, команда и подразделение — на начало попытки.
  Последующие переводы не меняют прошлую конверсию. Зоны руководителей
  считаются без дублей; отсутствие истории показывается явно.
- **Пересчёт:** единый момент среза; поздние данные уточняют исходную когорту.
  Неизвестные значения не заменяются нулями.

Бизнес-правила первой версии закреплены в
[AI-351](https://jira.centrofinans.ru/browse/AI-351). Задачу можно брать
в реализацию: следующий этап — привязка полей, расчёт и числовая сверка.
Производственные показатели пока не изменены.
