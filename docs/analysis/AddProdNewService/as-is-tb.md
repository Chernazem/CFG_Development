# As-is: дополнительные продукты в ТБ

Конфигурация: `repos/conf-main`. В метаданных две подсистемы с одним синонимом:

- `Подсистемы._ДополнительныеПродукты` - UI и прикладной состав (НСИ, документы, регистры).
- `Подсистемы.ДополнительныеПродукты` - роли и часть объектов доступа, в командный интерфейс не входит.

Термин «оффер» в `tb_api` относится к **предложению займа** (`loan_offer`). Подбор доппродуктов в 1С - это подбор **программ страхования / дополнительных продуктов**, не loan offer.

## Процесс выдачи

```text
ЗаявкаНаВыдачуЗайма
  -> подбор доступных программ (офис: форма ПодборДополнительныхПродуктов;
     remote: GetClientAvailableAdditionalProducts)
  -> выбор клиента / отказ
  -> запись в Справочники.ДополнительныеРеквизитыДополнительногоПродукта
     (владелец = заявка; ТЧ ДополнительныеПродукты)
  -> стоимость влияет на сумму оформления, график, лимиты КЛ
  -> заключение: ДоговорыКонтрагентов + ИзменениеУсловийДоговораЗайма
  -> УправлениеДополнительнымиПродуктами.СформироватьДокументыДополнительныхПродуктов
  -> ДоговорДополнительногоПродукта* / ДоговорСтрахования*
  -> РС УсловияДополнительныхПродуктов, РС СостоянияДополнительныхПродуктов,
     РН СтрахованиеОтНС
  -> если способ включения в тело = включать: сумма займа растет, затем отдельное ППИ
  -> иначе состояние ОжидаетОплаты / оплата вне тела
  -> печать / файлы ЛК / лицензионный ключ
```

Офис: подбор встроен в шаг условий заявки (`ШагУсловия` / `ШагВыборДополнительныхПродуктов`). Если блок видим, переход без подбора или явного отказа блокируется.

Remote / ЛК / МП / конвейер: те же модули через `tb_api` и `ОбщиеМодули.ПрограммныйИнтерфейсКредитныйКонвейер`.

## Три заявленных блока и их владельцы в 1С

### 1. Подбор оффера по заявке

| Что | Где |
| --- | --- |
| API | `GetClientAvailableAdditionalProducts` -> `ОбщиеМодули.ПрограммныйИнтерфейсДополнительныеПродукты.ПодобратьДополнительныеПродукты` |
| Офис | форма `ПодборДополнительныхПродуктов` через `СтрахованиеПовтИсп.ДоступныеСтраховыеПродукты` / `УправлениеДополнительнымиПродуктамиКлиент.ПодборДополнительныхПродуктовНаФорме` |
| Ядро матчинга | `ОбщиеМодули.СтрахованиеСервер.ЗаполнитьПараметрыСтрахованияПоКонтрагенту` |
| Вход | тарифы подразделения (`РС ТарифыСтрахования`), СКД отбора в `Справочники.НастройкиДополнительныхПродуктов`, вид займа, канал продаж, сумма/срок |
| Выход | набор программ с рассчитанной стоимостью и описанием |

Дополнительно API сворачивает доступность на min и max сумме займа. Черный список **внутри подбора не фильтруется**.

### 2. Фиксация выбранных клиентом продуктов

| Что | Где |
| --- | --- |
| API | `EditLoanRequestAdditionalProducts` / `GetLoanRequestAdditionalProducts` |
| Хранение | `Справочники.ДополнительныеРеквизитыДополнительногоПродукта` (не регистр) |
| Запись офис | `ОбщиеМодули.УправлениеДополнительнымиПродуктами.ЗаписатьДополнительныеПродуктыСФормы` |
| Запись remote | `ПрограммныйИнтерфейсДополнительныеПродукты.ИзменитьСписокДополнительныхПродуктовЗаявкиНаВыдачуЗайма` |
| Расчет цены | `РасчетУсловийДополнительногоПродукта` / `РассчитатьСтоимостьПродукта` |

Ограничения, уже зашитые в 1С:

- одна программа на один дополнительный продукт;
- для видов операций Продление и Оплата способ включения принудительно `ИсключатьИзТелаЗайма`;
- обязательные продукты из `РС ОбязательныеДополнительныеПродукты` (вид займа + канал продаж) запрещают отказ;
- перед уходом с шага условий сумма строки пересчитывается; расхождение блокирует переход.

### 3. Фиксация активации / оплаты

| Что | Где |
| --- | --- |
| Формирование договоров | `УправлениеДополнительнымиПродуктами.СформироватьДокументыДополнительныхПродуктов` после ИУ |
| Состояние | `РС СостоянияДополнительныхПродуктов`: `Заключен` или `ОжидаетОплаты` |
| Учет в теле/графике | `РН СтрахованиеОтНС`, `РС УсловияДополнительныхПродуктов.СпособВключенияВТелоЗайма` |
| Оплата при включении в тело | Сумма займа увеличивается, **затем** отдельное `ПлатежноеПоручениеИсходящее` на оплату доппродукта (не ИУ и не «оплата внутри выдачи») |
| Оплата вне тела | `ОплатаЧерезПлатежнуюСистему`; при продлении - `РС ДополнительныеПродуктыПриПродленииКОплате` и РЗ `ОплатаДополнительныхПродуктовПриПродлении` |

Активация в смысле 1С - это **проведение договора продукта и движений**, а не отдельный HTTP-факт «paid». Лицензионный ключ (`GetAdditionalProductLicenseKey`) - отдельный пост-оформительный контур.

## Точки встраивания в выдачу

| Контур | Точка |
| --- | --- |
| Офис новая заявка | `ШагУсловия` / `ШагВыборДополнительныхПродуктов` -> `ПодборДополнительныхПродуктов` -> `ШагКомплектДокументов` |
| Офис КЛ / транш | тот же механизм, см. `repos/conf-main/docs/loan-request/office-loan-request/credit-line` |
| Онлайн-выдача | `ОбщиеМодули.ЗаявкаНаВыдачуЗаймаСервер.ЗаписатьДопРеквизитыДопПродуктаПоЗаявкеПриВыдачеОнлайнЗайма`, `СформироватьДокументыДополнительныхПродуктовПриВыдачеОнлайнЗайма` |
| Кредитный конвейер | `ОбщиеМодули.ПрограммныйИнтерфейсКредитныйКонвейер` вызывает формирование документов после ИУ |
| tb_api | группа `ОперацииДополнительныхПродуктов` |

- `GetClientAvailableAdditionalProducts`
- `EditLoanRequestAdditionalProducts`
- `GetLoanRequestAdditionalProducts`
- `GetClientAdditionalProducts` (issued/paid; в docs есть пометка, что handler может отсутствовать)
- `GetAdditionalProductDescription` (deprecated)

- `GetAdditionalProductLicenseKey`
- `GetKeyElementsAdditionalProducts`
- `GetReissueTrancheAvailableAdditionalProducts`
- `GetBanners`

## НСИ, без которой подбор не воспроизводится

- `Справочники.ДополнительныеПродукты` - тип продукта, виды документов договора/оплаты, каналы продаж.
- `Справочники.ПрограммыСтрахования` - то, что реально выбирает клиент.
- `Справочники.НастройкиДополнительныхПродуктов` - цена, сроки, СКД-отбор доступности.
- `РС ТарифыСтрахования` - привязка программ к подразделению.
- `Справочники.СпособыВключенияВТелоЗайма` - включать / исключать.
- `Справочники.СостоянияДополнительныхПродуктов` - Заключен / ОжидаетОплаты / Отменен.
- Документ `УстановкаОбязательныхДополнительныхПродуктов` -> `РС ОбязательныеДополнительныеПродукты`.

## Что в 1С нельзя выкинуть даже после выноса «мозга»

Пока займ, график, касса и регламентированный учет живут в ТБ, в 1С остаются:

- проведение `ДоговорДополнительногоПродукта*` и движений;
- влияние стоимости на тело займа, график, лимиты КЛ, 151-ФЗ, ИУ;
- ППИ / кассовые чеки / оплата через платежную систему;
- печать полисов и заявления (как минимум потребление payload);
- журнал документов заявки, отмены, возвраты, мотивация, агентские условия.

Дублирование на пилоте означает: сервис получает факты подбора/выбора/оплаты, 1С продолжает создавать свои документы и движения.
