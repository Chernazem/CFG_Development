# Обработка очереди к завершению РСД

## Точка входа

Регламентное задание вызывает `РаботаСРефинансированиемСобственныхДоговоровСерверСлужебный.ОбработкаОчередиКЗавершениюРСД`.

Стек основного запуска:

1. `ОбработкаОчередиКЗавершениюРСД`
2. `ОбщегоНазначения.ПриНачалеВыполненияРегламентногоЗадания`
3. `ОбработатьОчередьКЗавершениюРСД`
4. `УдалитьИзОчередиНеактуальныеЗаписиОбОшибках`
5. `ДобавитьВОчередьОплаченные`
6. `ТекстЗапросаОбработкаОчередиКЗавершениюРСД`
7. фоновые задания `ОбработатьПорциюКЗавершению`
8. `ЗавершитьРефинансированиеСобственногоДоговора`
9. `ПрограммныйИнтерфейсРефинансированиеСобственногоДоговора.ЗавершитьРефинансированиеДоговора`
10. `УдалитьИзОчередиКЗавершению` или `ЗафиксироватьОшибкуПриЗавершении`

## Управление параллельностью

`ОбработатьОчередьКЗавершениюРСД` читает настройки из `РаботаСРефинансированиемСобственныхДоговоровСерверПовтИсп.НастройкиРефинансированияСобственногоДоговора()`. Если настройки не заполнены, регламент пишет ошибку в журнал и завершает работу.

Перед выборкой данных проверяются активные фоновые задания с наименованием `ОбработатьОчередьКЗавершениюРСД`. Регламент ожидает их завершения до 20 секунд. Если хотя бы одно задание остается активным, новая волна обработки не стартует.

Размер рабочей выборки ограничивается произведением `МаксимальноеКоличествоПотоковЗавершенияОчереди` и `КоличествоВОдномПотокеЗавершенияОчереди`. Далее массив договоров делится на порции и каждая порция запускается через `ДлительныеОперации.ВыполнитьВФоне`.

## Читаемые объекты базы

Основная очередь:

- `РегистрСведений.ОчередьКЗавершениюРефинансированияСобственногоДоговора` — читаются записи со статусом `ОжидаетЗавершения`, а также устаревшие записи со статусом `Ошибка`.

Подготовка новых записей очереди:

- `РегистрСведений.РефинансированныеСобственныеДоговоры` — ищутся договоры в статусе `НаОформлении` с датой рефинансирования после начала текущего дня.
- `РегистрСведений.СоответствияОперацийКаналамПродаж` — отбор каналов продаж для операции РСД.
- `РегистрНакопления.Продажи` — связь оформленного договора с каналом продаж.
- `РегистрНакопления.РасчетыПоЗаймам` — проверка факта платежа после даты рефинансирования.
- `Документ.ЗаявкаНаВыдачуЗайма` — используется через ссылку из регистра рефинансированных договоров для определения вида операции и сценария обработки.

Внутри завершения через программный интерфейс дополнительно затрагиваются объекты процесса рефинансирования договора, но непосредственная детализация этих изменений находится в вызываемом модуле `ПрограммныйИнтерфейсРефинансированиеСобственногоДоговора`.

## Изменяемые и создаваемые объекты базы

- `РегистрСведений.ОчередьКЗавершениюРефинансированияСобственногоДоговора`:
  - добавляется запись на завершение для оплаченного обычного РСД;
  - удаляются устаревшие записи с ошибкой;
  - удаляется запись после успешного завершения договора;
  - при ошибке обновляются статус `Ошибка` и `ТекстОшибки`.
- Данные процесса рефинансирования собственного договора изменяются через `ПрограммныйИнтерфейсРефинансированиеСобственногоДоговора.ЗавершитьРефинансированиеДоговора`.
- Блокировки оплат могут быть сняты для договоров сценария РСД с движением средств, если обнаружена причина `ОжидаетсяМинимальнаяОплатаДляРефинансированияСобственногоДоговора`.

## Что, куда и когда

На старте регламент приводит очередь в рабочее состояние: удаляет вчерашние ошибки, затем на основании оплат за текущий день добавляет обычные РСД в очередь завершения. После этого он берет из очереди только записи `ОжидаетЗавершения` и передает их в фоновые потоки.

Каждый поток завершает договор через программный интерфейс. Если интерфейс возвращает ошибку или возникает исключение, текст ошибки фиксируется в той же записи очереди. Если завершение прошло успешно, запись удаляется, а дальнейшее состояние договора уже отражается в регистрах и документах процесса рефинансирования.
