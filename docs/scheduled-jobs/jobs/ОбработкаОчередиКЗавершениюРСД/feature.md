# Обработка очереди к завершению РСД

## Назначение

Регламент завершает процессы рефинансирования собственного договора, которые уже дошли до стадии оформления и ожидают финального закрытия. Он берет договоры из очереди, пытается завершить рефинансирование и убирает успешно обработанные записи из очереди.

## Когда запускается

Задание предопределено в конфигурации, но в поставке отключено (`Use = false`). При включении оно запускается по настройкам регламентного задания и дополнительно ограничивается настройками рефинансирования: сколько потоков можно запустить и сколько договоров передавать в один поток.

Перед запуском новой обработки регламент проверяет, нет ли уже активных фоновых заданий с таким же назначением. Если такие задания еще работают, регламент ждет их завершения ограниченное время и затем пропускает текущий запуск, чтобы не обрабатывать одну очередь параллельно несколькими волнами.

## Бизнес-логика

Сначала регламент очищает очередь от устаревших записей с ошибками за прошлые дни. Это позволяет сегодняшнему запуску повторно работать только с актуальными ошибками и не держать старые неуспешные попытки в рабочей выборке.

Затем он ищет договоры, по которым после начала рефинансирования появилась оплата. Для обычного РСД такие договоры добавляются в очередь завершения со статусом ожидания завершения. Для сценария РСД с движением средств регламент не добавляет запись в обычную ветку, а снимает блокировку оплаты с причиной ожидания минимальной оплаты, потому что дальнейшее завершение идет отдельным регламентом РСДДС.

После подготовки очереди выбираются договоры со статусом `ОжидаетЗавершения`. Выборка упорядочена по дате добавления, чтобы первыми обрабатывались более старые записи. Найденные договоры разбиваются на порции и передаются в фоновые задания.

В каждой порции по каждому договору вызывается завершение рефинансирования. При успехе запись удаляется из очереди. При ошибке запись остается в очереди, получает статус `Ошибка` и текст причины. Такая запись может быть очищена следующим запуском после смены дня или разобрана вручную по журналу и содержимому очереди.

## Результат работы

После успешной обработки договор считается завершенным в рамках процесса РСД, а запись в очереди исчезает. Если завершение не удалось, очередь сохраняет ошибку по договору, чтобы проблему можно было диагностировать и не потерять факт неуспешной попытки.
