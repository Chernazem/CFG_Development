# Обработка очереди получения документов по банкротам

## Точка входа

Регламентное задание вызывает `РаботаССервисомБанкротовСлужебный.ОбработкаОчередиПолученияДокументовПоБанкротам`.

Стек выполнения:

1. `ОбработкаОчередиПолученияДокументовПоБанкротам`
2. `ОбщегоНазначения.ПриНачалеВыполненияРегламентногоЗадания`
3. `СтандартныеПодключенияПовтИсп.ПолучитьПодключение(ОчередьОтветовПолученияДокументовПоБанкротам)`
4. `ОчередьСообщений.НовыйПодписчик`
5. `ПолучитьДанныеДляОтвета`
6. `ОбработатьСообщениеОтвета`
7. `СсылкаНаФайлИзОтветаСервисаPDF`
8. `СкачатьФайлНаСервереHTTPЗапрос`
9. `РаботаСФайлами.ДобавитьФайл`
10. при необходимости `РаботаСБезнадежнойЗадолженностью.СписаниеЗадолженностиБанкротов`

## Читаемые объекты базы

- `Документ.ЗапросИнформацииОБанкротстве.Сообщения` — поиск исходного сообщения по `СообщениеGUID = CorrelationId`; учитываются только проведенные и не помеченные на удаление документы.
- `Документ.ЗапросИнформацииОБанкротстве` — читаются состояние дела, тип банкрота, флаг необходимости завершения дела, организации в кредиторах.
- `СтандартныеПодключения` по виду `ОчередьОтветовПолученияДокументовПоБанкротам` — очередь, откуда читаются ответы сервиса.

Связанный метод отправки запросов `ЗапроситьФайл` использует подключения `ОчередьПолученияДокументовПоБанкротам` и `ОчередьОтветовПолученияДокументовПоБанкротам`, задавая `ReplyTo` и `CorrelationID = СообщениеGUID`.

## Изменяемые и создаваемые объекты базы

- Присоединенные файлы документа `ЗапросИнформацииОБанкротстве` — создается PDF-файл через `РаботаСФайлами.ДобавитьФайл`.
- `Документ.ЗапросИнформацииОБанкротстве` — для судебного банкротства состояние может быть изменено на `ДелоЗавершено` с записью в режиме проведения.
- Объекты списания безнадежной задолженности создаются или изменяются внутри `РаботаСБезнадежнойЗадолженностью.СписаниеЗадолженностиБанкротов`.

## Что, куда и когда

Обработчик живет до истечения времени жизни фонового задания и читает сообщения с таймаутом 60 секунд. По каждому сообщению он сначала находит документы, к которым относится `CorrelationId`. Если документов нет, сообщение просто подтверждается.

Если сервис вернул `status = success` и `data.file_url`, файл скачивается отдельным HTTP GET. Двоичные данные помещаются во временное хранилище и прикрепляются к каждому найденному документу запроса. После добавления файла проверяются доменные условия завершения банкротного дела и списания задолженности.

При исключении регламент завершает цикл, подтверждает текущее сообщение и пишет подробную ошибку в журнал. При ошибочном ответе сервиса или неудачном скачивании сообщение также подтверждается, а проблема остается в журнале.
