# Обработка очереди к завершению РТ

## Назначение

Регламент завершает рефинансирование платежей траншей кредитных линий. Он отслеживает записи очереди, где рефинансирование либо ждет минимальной оплаты, либо уже готово к финальному завершению.

## Когда запускается

Задание предопределено, в поставке отключено (`Use = false`). В расписании задан повтор каждые 30 секунд. При работе регламент использует настройки потоковой обработки из общих настроек рефинансирования.

Новый запуск не стартует, если еще активны фоновые задания предыдущей обработки очереди РТ. Это защищает очередь от одновременного изменения одних и тех же договоров.

## Бизнес-логика

Сначала регламент очищает устаревшие записи с ошибками за прошлые дни. Затем выбирает сегодняшние записи очереди рефинансирования траншей в двух статусах:

- `ОжидаетПодтверждениеПеревода` — нужно проверить, поступила ли минимальная оплата для завершения рефинансирования;
- `ОжидаетЗавершения` — можно выполнять финальное завершение.

Для записей, ожидающих подтверждения перевода, регламент проверяет, не находится ли договор в пересчете начислений. Если договор в пересчете, обработка этой записи откладывается. Если пересчета нет и поступившая оплата покрывает рассчитанную минимальную сумму, регламент снимает блокировку оплаты и переводит запись очереди в статус `ОжидаетЗавершения`.

Для записей в статусе `ОжидаетЗавершения` вызывается завершение рефинансирования транша. При успехе запись удаляется из очереди. При ошибке в очереди сохраняется статус `Ошибка` и текст причины.

## Результат работы

Регламент либо подготавливает запись к завершению после подтверждения минимальной оплаты, либо завершает рефинансирование транша полностью. Неуспешные попытки не теряются: они остаются в очереди с диагностическим текстом.
