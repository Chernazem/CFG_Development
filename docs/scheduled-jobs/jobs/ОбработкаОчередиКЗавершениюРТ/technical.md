# Обработка очереди к завершению РТ

## Точка входа

Регламентное задание вызывает `РефинансированиеТраншейСлужебный.ОбработкаОчередиКЗавершениюРТ`.

Стек выполнения:

1. `ОбработкаОчередиКЗавершениюРТ`
2. `ОбщегоНазначения.ПриНачалеВыполненияРегламентногоЗадания`
3. `ОбработатьОчередьКЗавершениюРТ`
4. `УдалитьИзОчередиНеактуальныеЗаписиОбОшибках`
5. `ТекстЗапросаДоговоровДляЗавершенияРТ`
6. фоновые задания `ОбработатьПорциюКЗавершениюПоРТ`
7. `ОбработатьДанныеТранша`
8. для ожидания перевода: `ПараметрыРасчетаМинимальнаяСуммаОплатыДляЗавершенияРефинансирования`, `МинимальнаяСуммаОплаты`, `СнятьБлокировкуНаОплатуПоДоговору`, `ОчередьКЗавершениюРефинансированияТраншей.ИзменитьСтатусВОчередиНаЗавершение`
9. для завершения: `ПрограммныйИнтерфейсРефинансированиеТраншей.ЗавершитьРефинансированиеТранша`
10. `ОчередьКЗавершениюРефинансированияТраншей.УдалитьИзОчереди` или `ЗафиксироватьОшибкуПриЗавершении`

## Отбор данных

Запрос выбирает записи из `РегистрСведений.ОчередьКЗавершениюРефинансированияТраншей` за текущий день в статусах `ОжидаетПодтверждениеПеревода` и `ОжидаетЗавершения`. Старые ошибочные записи предварительно удаляются отдельным запросом по статусу `Ошибка` и дате добавления меньше начала текущего дня.

Для обогащения строк очереди запрос читает:

- `РегистрСведений.РефинансированныеТранши` — данные рефинансирования транша и статус `НаОформлении`;
- `РегистрСведений.СостояниеДоговоровЗайма` — актуальное состояние договора;
- `Документ.ЗаявкаНаВыдачуЗайма` — заявка, канал продаж и контекст выдачи;
- `Справочник.ДоговорыКонтрагентов` — организационная аналитика договора: подразделение, команда, сквод, трайб;
- `РегистрНакопления.РасчетыПоЗаймам` — поступившая оплата;
- `РегистрСведений.ОчередьПересчетаНачислений` и `РегистрСведений.ОчередьОбновленияКешаНачислений` — признак, что договор сейчас находится в пересчете.

## Изменяемые объекты базы

- `РегистрСведений.ОчередьКЗавершениюРефинансированияТраншей`:
  - удаляются устаревшие ошибки;
  - статус меняется с `ОжидаетПодтверждениеПеревода` на `ОжидаетЗавершения`, когда минимальная оплата подтверждена;
  - успешная запись удаляется;
  - при ошибке записываются статус `Ошибка` и `ТекстОшибки`.
- Блокировки оплат по договору снимаются для причины `ОжидаетсяМинимальнаяОплатаДляРефинансированияПлатежаТранша`.
- Финальные изменения рефинансирования транша выполняет `ПрограммныйИнтерфейсРефинансированиеТраншей.ЗавершитьРефинансированиеТранша`.

## Что, куда и когда

Если запись находится в статусе `ОжидаетПодтверждениеПеревода`, регламент не завершает ее сразу. Он рассчитывает минимальную сумму оплаты на начало текущего дня с добавлением одной секунды, подставляет данные договора и организационную аналитику, затем сравнивает расчет с фактически поступившей оплатой. Только после этого снимается блокировка оплаты и запись переводится в `ОжидаетЗавершения`.

Если запись уже в `ОжидаетЗавершения`, регламент передает структуру данных в программный интерфейс завершения РТ. При успешном результате очередь очищается. Если интерфейс вернул ошибки или возникло исключение внутри фонового задания, запись остается в очереди со статусом `Ошибка`.

Каждая строка порции обрабатывается в собственной транзакции, поэтому сбой по одному договору не откатывает всю порцию.
