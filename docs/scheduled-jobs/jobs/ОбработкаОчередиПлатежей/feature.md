# Обработка очереди платежей

## Назначение

Регламент поддерживает обработку входящих платежей от платежных систем. Он запускает нужное количество фоновых обработчиков, которые читают сообщения из брокера, проверяют платеж и создают в 1С документы оплаты.

## Когда запускается

Задание предопределено, но в поставке отключено (`Use = false`). В явном файле расписания для задания нет отдельного `Schedule.xml`; запуск определяется настройками регламентных заданий в базе. Дополнительно работа зависит от константы `ИспользоватьОбработкуПлатежей`.

Количество потоков и тип брокера берутся из активной настройки обработки платежей. Для RMQ используется заданное количество потоков. Для Kafka количество потоков определяется количеством разделов темы.

## Бизнес-логика

Регламент сам не создает платежные документы. Он поддерживает пул фоновых обработчиков `ОбработатьОчередьПлатежей`. Каждый обработчик читает сообщения из выбранного брокера:

- RMQ — сообщение обрабатывается с отправкой ответа в `ReplyTo`/`CorrelationId`;
- Kafka — сообщение обрабатывается с ручной фиксацией смещения после успешной обработки.

Содержимое сообщения десериализуется в параметры платежа. Затем выполняются проверки обязательных параметров и уникальности идентификатора платежа. Если платеж еще не был загружен, по объекту оплаты создается соответствующий документ:

- оплата по договору контрагента;
- оплата по заявке на выдачу займа;
- оплата дополнительного продукта.

После успешного создания документа могут отправляться уведомления ответственным лицам об оплате.

## Результат работы

Корректный уникальный платеж превращается в документ оплаты в 1С. Дубликаты не загружаются повторно. Ошибочные RMQ-сообщения получают ответ с описанием ошибки, а Kafka-сообщения при исключении отправляются в отдельную очередь ошибок.
