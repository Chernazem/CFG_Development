# Обработка очереди обновления данных мониторов

## Назначение

Регламент обновляет данные рабочих мониторов после изменений в договорах, платежах, звонках, контрагентах и других объектах. Вместо полного пересчета всех мониторов он обрабатывает очередь конкретных договоров или контрагентов, по которым были зарегистрированы изменения.

## Когда запускается

Задание предопределено, но в поставке отключено (`Use = false`). Расписание настроено на частый запуск с повтором каждые 10 секунд. Такой режим нужен, чтобы мониторы быстро подтягивали изменения после пользовательских и интеграционных операций.

## Бизнес-логика

Записи в очередь попадают при изменении источников данных: платежных документов, начислений, переносов предоплаты, телефонных звонков, корректировок займа, оплат через платежную систему и карточек контрагентов. Для каждого вида монитора определяется предмет обновления: договор или контрагент.

Регламент читает из очереди порцию записей, группирует их по виду монитора и запускает обновление соответствующей витрины:

- монитор должников;
- монитор неактуальных телефонов;
- монитор активных клиентов;
- монитор неактивных клиентов.

Если в порции есть несколько видов мониторов, обновление выполняется параллельно фоновыми заданиями. Если вид один, обработка идет в текущем сеансе. Для договорных мониторов дополнительно учитывается очередь пересчета начислений: договоры, которые еще находятся в пересчете, не обновляются до завершения пересчета.

## Результат работы

После успешного обновления записи удаляются из очереди. Витрины мониторов получают актуальные данные только по измененным договорам или контрагентам, без массового пересчета всей базы.
