# Обработка очереди обновления данных мониторов

## Точка входа

Регламентное задание вызывает `ОбновлениеДанныхМониторовСлужебный.ОбработкаОчередиОбновленияДанныхМониторов`.

Стек выполнения:

1. `ОбработкаОчередиОбновленияДанныхМониторов`
2. `ОбщегоНазначения.ПриНачалеВыполненияРегламентногоЗадания`
3. `ОбработкаОчереди`
4. `ПолучитьДанныеДляОбработкиОчереди`
5. `ЗаполнитьДанные`
6. для договорных мониторов `ОпределитьДоговорыСЗавершеннымПересчетом`
7. `ЗаполнениеДанныхМонитора`
8. `УдалитьЗаписиИзОчереди`
9. при нескольких видах мониторов: фоновые задания `ОбработатьДанныеОчередиВПотоках`

## Читаемые объекты базы

- `РегистрСведений.ОчередьОбновленияДанныхМониторов` — основная очередь. Читаются `Предмет`, `ВидМонитора`, `ПериодОбновления`, сортировка идет по периоду обновления.
- `РегистрСведений.ОчередьПересчетаНачислений` — для договорных мониторов отфильтровываются договоры, которые еще находятся в пересчете начислений.
- Настройки подсистемы `ЗаймыМониторинг.НастройкиПодсистемы()` — размер порции обновления.
- Константа `ИспользоватьКонтрольАктуальностиРасчетов` — включает или отключает фильтрацию договоров по очереди пересчета.

Заполнение конкретных мониторов делегируется профильным модулям:

- `МониторДолжниковСервер.ЗаполнениеДанныхМонитораПоДоговорам`;
- `МониторНеактуальныхТелефоновСлужебный.ЗаполнениеДанныхМонитораПоДоговорам`;
- `МониторАктивныхКлиентовСлужебный.ЗаполнениеДанныхМонитораПоКонтрагентам`;
- `МониторНеактивныхКлиентовСлужебный.ЗаполнениеДанныхМонитораПоКонтрагентам`.

## Изменяемые объекты базы

- `РегистрСведений.ОчередьОбновленияДанныхМониторов` — записи удаляются после успешного обновления.
- Регистры данных мониторов изменяются внутри профильных модулей заполнения: для должников и неактуальных телефонов по договорам, для активных и неактивных клиентов по контрагентам.
- При регистрации изменений в очередь добавляются записи с `Предмет`, `ВидМонитора` и текущим `ПериодОбновления`.

## Что, куда и когда

Порция выбирается из очереди в порядке старейшего `ПериодОбновления`; размер порции берется из настроек мониторинга. Результат запроса группируется по `ВидМонитора`, потому что каждый монитор имеет свой обработчик и свой тип предмета.

Для видов `МониторДолжников` и `МониторНеактуальныхТелефонов` предметом считается договор. Перед обновлением договоры, найденные в очереди пересчета начислений, исключаются из текущей порции и остаются в очереди обновления мониторов до следующих запусков. Для видов `МониторАктивныхКлиентов` и `МониторНеактивныхКлиентов` предметом считается контрагент.

После успешного вызова профильного заполнения регламент удаляет из очереди ровно те записи, которые передавались в обработку: по предмету, виду монитора и периоду обновления.
