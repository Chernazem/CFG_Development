# Обработка очереди личного кабинета

## Точка входа

Регламентное задание вызывает `ТБ_ОбменСЛичнымКабинетом.ОбработкаОчередиЛичногоКабинета`.

Стек запуска обработчиков:

1. `ОбработкаОчередиЛичногоКабинета`
2. `ОбщегоНазначения.ПриНачалеВыполненияРегламентногоЗадания`
3. `ЗначенияКонстантПовтИспСервер.КоличествоПотоковОбработкиОчередиЛичногоКабинетаПолучить`
4. проверка активных фоновых заданий `ОбработчикОчередиЛичногоКабинета`
5. `ДлительныеОперации.ВыполнитьВФоне("ТБ_ОбменСЛичнымКабинетом.ОбработчикОчередиЛичногоКабинета")`

Стек обработки сообщения:

1. `ОбработчикОчередиЛичногоКабинета`
2. `СтандартныеПодключенияПовтИсп.ПолучитьПодключение(ОчередьЛичныйКабинет)`
3. `ОчередьСообщений.НовыйПодписчик`
4. `Получатель.ПолучитьСообщение`
5. `ОбработкаИтерации`
6. `ОбработатьСообщение`
7. `ТБ_ОбменыДаннымиСервер.ДесериализоватьJSON`
8. `СформироватьОтветПоТипуСобытия`
9. бизнес-обработчик по `action`
10. `ОтправитьОтвет`
11. `ОчередьСообщений.НовыйИздатель("http-proxy")`
12. `ОтправитьСообщенияЧерезRPC`

## Управление обработчиками

Регламент не читает очередь напрямую. Он поддерживает пул фоновых заданий с наименованием `ОбработчикОчередиЛичногоКабинета`. Требуемый размер пула берется из константы `КоличествоПотоковОбработкиОчередиЛичногоКабинета`.

Фоновый обработчик получает стандартное подключение `ОчередьЛичныйКабинет`. Если подключение не найдено, обработчик пишет ошибку и завершается. Таймаут чтения берется из подключения, а если он не заполнен, используется 60000 мс. Чтение идет в цикле до истечения времени жизни фонового задания. Перед обработкой каждого сообщения проверяется отсутствие активной транзакции.

## Маршрутизация сообщений

`СформироватьОтветПоТипуСобытия` проверяет обязательные поля входящего JSON и маршрутизирует запрос по `action`.

Прямые сценарии:

- `CreateRequest` -> `СоздатьЗаявкуИНачатьВерификацию`;
- `ApproveRequest` -> `ПройтиВерификациюОтправитьДеньги`;
- `CheckPayment` -> `ПроверитьСтатусПеревода`;
- `BankCards_AddCard` -> `ДобавитьБанковскуюКартуКонтрагентаЧерезОчередь`.

Групповые сценарии:

- онлайн-займ: `CreateRequest_OnlineLoan`, `CheckCounterparty_OnlineLoan`, `CreateAndUploadDocuments_OnlineLoan`, `StartVerification_OnlineLoan`, `ApproveRequestAndSendPayment_OnlineLoan` передаются в `ОбработатьСобытие_ВыдачаОнлайнЗайм`;
- рефинансирование договора: `StartClientVerification`, `EndClientVerification`, `GetRefinancingOwnContractDetails`, `RefinancingOwnContractStart`, `RefinancingOwnContractEnd` передаются в `ОбработатьСобытие_РефинансированиеДоговора`.

Если `action` пустой или неизвестный, сообщение логируется и ответ не отправляется.

## Читаемые объекты базы

Для базовых сценариев личного кабинета читаются:

- `Справочник.Контрагенты` — поиск клиента по `client_id`;
- контактная информация клиента для получения мобильного телефона;
- `Документ.ЗаявкаНаВыдачуЗайма` — поиск заявки по `request_id`, чтение текущего шага и статуса оформления;
- данные проверок клиента и верификации через модули `ВерификацияКонтрагентов` и `ЗаявкаНаВыдачуЗаймаСервер`;
- статус платежа по заявке через `ЗаявкаНаВыдачуЗаймаСервер.ПолучитьСтатусОплаты`.

Групповые обработчики онлайн-займа, РСД и добавления карты читают свои доменные объекты внутри соответствующих процедур. Регламентная точка отвечает за доставку и диспетчеризацию сообщения.

## Изменяемые и создаваемые объекты базы

В прямых сценариях:

- `CreateRequest` создает документ `ЗаявкаНаВыдачуЗайма` для канала продаж `ВЛичномКабинете` через `ЗаявкаНаВыдачуЗаймаСервер.СоздатьЗаявкуНаВыдачуТранша`, затем создает или запускает верификацию через `ВерификацияКонтрагентов.НачатьВерификацию`.
- `ApproveRequest` после успешной верификации и проверок формирует документы по заявке и запускает перевод на карту клиента через `ЗаявкаНаВыдачуЗаймаСервер.ВыполнитьПереводНаКартуКлиента`.
- `CheckPayment` при статусе платежа `Принят` переводит заявку на шаг `Завершено`; при статусе `Ошибка` отменяет оформление и переводит заявку на шаг `Отказано` с причиной `ОшибкаВТранзакции`.
- `BankCards_AddCard` изменяет данные банковских карт клиента через профильный обработчик добавления карты.

Внешний ответ не пишется в базу: он публикуется в очередь `http-proxy` с заголовками `URL = callback_url` и `Method = POST`.

## Подтверждение сообщений

`ОбработкаИтерации` подтверждает сообщение через `Получатель.СообщениеОбработано()`, если не выставлен флаг отклонения. Пустые сообщения также подтверждаются после логирования. В текущем коде при исключениях внутри `ОбработатьСообщение` ошибка пишется в журнал, но сообщение все равно подтверждается, если обработчик не установил `ОтклонитьСообщение`.
