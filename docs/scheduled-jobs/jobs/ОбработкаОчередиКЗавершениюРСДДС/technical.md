# Обработка очереди к завершению РСДДС

## Точка входа

Регламентное задание вызывает `РаботаСРефинансированиемСобственныхДоговоровСерверСлужебный.ОбработкаОчередиКЗавершениюРСДДС`.

Стек выполнения:

1. `ОбработкаОчередиКЗавершениюРСДДС`
2. `ОбщегоНазначения.ПриНачалеВыполненияРегламентногоЗадания`
3. `ОбработатьОчередьКЗавершениюРСДДС`
4. `ТекстЗапросаДоговораДляЗавершенияРефинансированияСДвижениемСредств`
5. фоновые задания `ОбработатьПорциюКЗавершениюПоРСДДС`
6. `ИзменитьСтатусВРегистреРефинансированныеСобственныеДоговоры`
7. `УдалитьИзОчередиЗавершенныеРСДДС`
8. при ошибке `ЗафиксироватьОшибкуПриЗавершении`

## Отбор данных

Исходная выборка строится по `РегистрСведений.ОчередьКЗавершениюРефинансированияСобственногоДоговора`. В обработку берутся записи со статусом `ОжидаетПодтверждениеСписания`.

Затем по этим договорам читается `РегистрСведений.СостояниеДоговоровЗайма`. Запрос получает последний статус по каждому договору и оставляет только договоры, где состояние равно `Справочник.СостоянияДоговораЗайма.ДоговорЗакрыт`.

Таким образом регламент не завершает РСДДС по самому факту наличия записи в очереди. Он ждет подтверждения закрытия рефинансируемого договора в регистре состояний договора займа.

## Управление параллельностью

Обработка использует настройки:

- `МаксимальноеКоличествоПотоковЗавершенияОчередиРСДДС`;
- `КоличествоВОдномПотокеЗавершенияОчередиРСДДС`.

Перед стартом проверяются активные фоновые задания с наименованием `ОбработатьОчередьКЗавершениюРСДДС`. Если за 20 секунд они не завершились, новый запуск прекращается. Рабочая выборка ограничивается общим объемом всех потоков, затем делится на массивы и передается в `ДлительныеОперации.ВыполнитьВФоне`.

## Читаемые объекты базы

- `РегистрСведений.ОчередьКЗавершениюРефинансированияСобственногоДоговора` — очередь договоров в статусе ожидания подтверждения списания.
- `РегистрСведений.СостояниеДоговоровЗайма` — актуальное состояние рефинансируемого договора.
- `РегистрСведений.РефинансированныеСобственныеДоговоры` — запись процесса РСД, статус которой меняется через менеджер регистра.

## Изменяемые объекты базы

- `РегистрСведений.РефинансированныеСобственныеДоговоры` — статус записи по рефинансируемому договору переводится в `СтатусыРефинансированияСобственногоДоговора.Оформлен`.
- `РегистрСведений.ОчередьКЗавершениюРефинансированияСобственногоДоговора` — успешная запись удаляется из очереди.
- При исключении в той же очереди фиксируются статус `Ошибка` и краткое описание причины.

## Транзакционность

Каждый договор в порции обрабатывается в отдельной транзакции. Внутри транзакции сначала обновляется статус в регистре рефинансированных собственных договоров, затем удаляется очередь. Это важно: договор не должен исчезнуть из очереди, если не удалось записать финальный статус.

При исключении транзакция отменяется, подробная ошибка пишется в журнал регистрации, а краткая причина сохраняется в очереди через `ЗафиксироватьОшибкуПриЗавершении`.
