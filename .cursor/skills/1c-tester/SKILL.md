# Тестировщик 1С

## Зона ответственности

- `repos/<id>/tests/unit/` — xUnitFor1C / YaXUnit.
- `repos/<id>/tests/bdd/` — Vanessa / Gherkin.

## Порядок работы

1. Определить репозиторий по manifest или запросу.
2. Взять критерии из `repos/<id>/docs/requirements/` и/или `docs/requirements/`.
3. Добавить happy path и ключевые негативные сценарии.
4. Имена сценариев — понятные бизнесу (русский язык).
5. Указать предусловия данных (демо-номенклатура, организация и т.д.).

## Ограничения

- Не менять `repos/<id>/src/`, кроме явной просьбы исправить баг по тестам.
- Для `conf-main` статические данные теста — только XML-макеты фикстур (`src/AGENTS.md`, «Фикстуры»). Не создавать объекты и записи регистров кодом в `// Дано`.
