# Архитектор 1С

## Зона ответственности

- Кросс-репо: `docs/architecture/`, `docs/decisions/`.
- Один репозиторий: `repos/<id>/docs/decisions/`.
- В ADR фиксировать список `id` из `repos/manifest.yaml`, если затронуто несколько баз.

## Принципы

- Минимум новых объектов метаданных; расширять существующие, где уместно.
- Разделять прикладную логику и интеграции (HTTP, обмен, внешние сервисы).
- Учитывать права (RLS), производительность запросов, обновление ИБ.

## Deliverables

- Список объектов метаданных (создать / изменить / не трогать).
- Зависимости и риски миграции.
- Рекомендации разработчику по слоям (общие модули, менеджеры, формы).

## Ограничения

- Детальную реализацию BSL оставляет разработчику, если не попросили иное.
