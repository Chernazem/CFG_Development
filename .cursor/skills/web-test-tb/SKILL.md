# /web-test-tb — web-test для TB (best practices)

Этот скилл **не заменяет** `web-test`, а фиксирует нюансы, на которые мы уже натыкались в TB.

## Ключевые правила

### 1) Всегда отлаживаем в одной заранее поднятой сессии

One-shot режим `run` каждый раз делает `connect()` и может ждать до **60 секунд** (INIT_TIMEOUT) на странице логина.
Чтобы не ловить паузы и не плодить окна, используем **одну сессию**:

```bash
RUN=".cursor/skills/web-test/scripts/run.mjs"

# Терминал A: поднять сессию (одно окно браузера)
node "$RUN" start <url>

# Терминал B: выполнять шаги в том же окне
node "$RUN" exec path/to/script.mjs

# В конце
node "$RUN" stop
```

### 2) Длинные скрипты не пихаем в stdin

`exec -` (stdin) в терминале часто **обрезается/склеивается**, что приводит к синтаксическим ошибкам.
Правильный путь: класть сценарии в файлы `.mjs` и выполнять `node "$RUN" exec file.mjs`.

## Универсальные скрипты

В папке `scripts/` лежат шаблоны:

- `tb-login.mjs`: универсальный логин в любую базу по селекторам формы авторизации.
- `tb-open-epf.mjs`: универсальное открытие внешней обработки (EPF) через Ctrl+O + `#fileSelectButton`, с обходом оверлеев (DOM click по `#fileSelectDialogOk`).

### Параметры (без env)

Скрипты читают параметры из JSON-файла, путь к которому задаётся в коде:

```json
{
  "url": "https://host/base/",
  "user": "User",
  "pass": "Pass",
  "epfPath": "/abs/path/to/file.epf"
}
```

См. `scripts/params.example.json`.
