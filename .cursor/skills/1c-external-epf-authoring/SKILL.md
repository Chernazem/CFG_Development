# 1C External EPF Authoring

## Цель

Стабильно делать внешние обработки 1С в формате файлов выгрузки, без поломки структуры и без ошибок `vrunner compileepf`.

## Обязательная структура

Пользователь обязан явно указать:

- `EPF_ROOT`: путь к каталогу, где лежат внешние обработки в формате выгрузки (например `src/vibe`, `src/epf`, `tools/epf` и т.п.)
- `EPF_NAME`: имя обработки (каталог и корневой XML), например `ИмяОбработки`

Далее в скилле используем \(EPF_DIR = EPF_ROOT/EPF_NAME\).

Для обработки `EPF_NAME`:

- Корневой XML обработки: `EPF_ROOT/EPF_NAME.xml`
- Папка обработки: `EPF_DIR/`
- Модуль объекта: `EPF_DIR/Ext/ObjectModule.bsl`
- Метаданные формы: `EPF_DIR/Forms/Форма.xml`
- XML формы: `EPF_DIR/Forms/Форма/Ext/Form.xml`
- Код формы: `EPF_DIR/Forms/Форма/Ext/Form/Module.bsl`
- Метаданные макета: `EPF_DIR/Templates/ИмяМакета.xml`
- Контент макета (табдок): `EPF_DIR/Templates/ИмяМакета/Ext/Template.xml`

## Частые ошибки (не допускать)

- Не класть `Form.xml` в `.../Ext/Form/Form.xml`.
- Не класть `Template.xml` в `.../Ext/Template/Template.xml`.
- Не переносить `EPF_NAME.xml` внутрь папки обработки.
- Не заменять UUID без необходимости.
- Не терять код модуля (проверять, что файл не пустой и не содержит мусор вроде `аыаы`).

## Базовый workflow

1. Взять за основу рабочую выгрузку из конфигуратора (или шаблон с корректной структурой).
2. Создать/обновить XML обработки, формы, макета и модуль формы.
3. Проверить, что пути и имена в XML совпадают с фактической структурой.
4. Проверить модуль формы: есть клиентская команда запуска и серверный код.
5. После каждого изменения кода `.bsl` и ОБЯЗАТЕЛЬНО перед сборкой прогнать статическую диагностику. Важно: КАЖДЫЙ изменённый модуль проверять отдельно (каждый файл `.bsl` — отдельный запуск диагностики), а не только модуль формы. Автоматически фиксировать замечания, не меняющие логику; по остальным — уточнять, что делать. Если диагностика не проходит/есть критичные проблемы — сборку НЕ запускать, пока не исправлено:
   - `lsp-skill diagnostics "<путьКИзменённомуМодулю.bsl>"`
   - пример: `lsp-skill diagnostics "EPF_DIR/Forms/Форма/Ext/Form/Module.bsl"`
   - пример: `lsp-skill diagnostics "EPF_DIR/Ext/ObjectModule.bsl"`
5. Собрать:
   - Сборку запускать только после обязательной `lsp-skill diagnostics` (см. пункт выше).
   - Перед сборкой ОБЯЗАТЕЛЬНО уточнить у пользователя параметры его локальной базы для запуска 1С:
     - `--ibconnection` (строка подключения вида `/F/...` или `/S...`)
     - `--v8version` (версия платформы 1С на машине пользователя, если в проекте/окружении vrunner это требуется)
     - имя пользователя (логин) ИБ: `--db-user`
     - при необходимости — пароль: `--db-pwd`
   - `vrunner compileepf EPF_DIR EPF_ROOT`
   - Если в `Form.xml`/атрибутах формы используются типы из конфигурации (например `cfg:DocumentRef.*`, `cfg:CatalogRef.*`) и сборка падает на XDTO/чтении XML — собирать с подключением к ИБ:
     - `vrunner compileepf EPF_DIR EPF_ROOT --ibconnection "<строкаПодключения>" --v8version "<8.3.xx.xxxx>" [--db-user "<логин>"] [--db-pwd "<пароль>"]`
6. Если `vrunner` создал вложенный путь вроде `EPF_ROOT/Users/.../src/EPF_NAME.epf`:
   - скопировать результат в `EPF_ROOT/EPF_NAME.epf`
   - удалить служебную папку `EPF_ROOT/Users`
7. Повторно проверить наличие итогового файла `EPF_ROOT/EPF_NAME.epf`.

## Проверки перед сдачей

- В `Module.bsl` есть рабочий код, а не заглушка.
- В `Form.xml` есть команда запуска и атрибуты, на которые ссылается код.
- В `Template.xml` реально есть данные/макет (если нужен по задаче).
- Файл `EPF_ROOT/EPF_NAME.epf` существует и обновлен по времени.

## Мини-шаблон модуля формы

```bsl
&НаКлиенте
Процедура Выполнить(Команда)
    Результат = ВыполнитьНаСервере();
    Результат.Показать("Результат");
КонецПроцедуры

&НаСервере
Функция ВыполнитьНаСервере()
    // Основной алгоритм
    Возврат Новый ТабличныйДокумент;
КонецФункции
```

## Отладка ошибок compileepf

Если ошибка общая и в логе "ошибка при чтении XML":

1. Сначала проверить структуру `Forms` и `Templates` (самая частая причина).
2. Сверить расположение `Form.xml` и `Template.xml` с обязательной структурой выше.
3. Проверить, что `EPF_ROOT/EPF_NAME.xml` лежит рядом с папкой `EPF_DIR/`.
4. Если ошибка связана с XDTO/типами (`cfg:*Ref.*`) — использовать `compileepf` с `--ibconnection` (см. workflow выше).
5. После фикса повторить `compileepf`.
