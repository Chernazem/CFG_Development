# Найти запрос 1С по сообщению Graylog (ТЖ DBMSSQL)

## Когда использовать

- Есть событие `DBMSSQL` из ТЖ / Graylog, нужно найти **исходный** текст на языке
  запросов 1С или фрагмент СКД в конфигурации.
- Вход: permalink, JSON-файл полей сообщения, или уже известные `Sql` + `Context`.

## Что нужно на входе

Поля сообщения (плоский JSON или `message.fields` / `fields`):

| Поле | Зачем |
|------|--------|
| `Sql` | скомпилированный SQL |
| `Context` | стек вызовов |
| `Infobase` | какая конфигурация / снимок schema |
| `client_session_id` | имя отчёта через eventlog, если в Context его нет |

Способ получения сообщения из Graylog **не фиксируем** — используй доступные
средства; в этом навыке важны только поля и алгоритм поиска в коде.

Для перевода `_InfoRg` / `_Document` / `_Fld` → имена 1С применяй навык
`1c-sql-translate` и снимок `schema` нужной базы (для ТБ ЦФГ —
`tb_cfg_dbschema/schema`).

## Важно

- SQL в ТЖ **сложнее** исходника: это компиляция платформы. Не ищи дословный SQL
  в BSL/макете и не требуй 1:1.
- Физические `_Document*` / `_InfoRg*` / `_AccumRg*` / `_Fld*` → **только** навык
  `1c-sql-translate` (CLI). Не разбирай `schema/` и не угадывай имена вручную.
- Если `Sql` начинается с `success` (native quick insert и т.п.) — это **не** текст
  запроса 1С; по такому сообщению исходник не ищут (Context может указывать на
  соседний `Запрос.Выполнить`, но тело SQL здесь отсутствует).
- **`EXISTS (...)` — маркер RLS** (`РАЗРЕШЕННЫЕ`). В исходном запросе 1С его нет.
  Для поиска **исключай** поддеревья `EXISTS` и связанные только с RLS таблицы
  (`ИдентификаторыОбъектовМетаданных`, `ТаблицыГруппДоступа` и т.п.).
- Шум платформы (не якоря): `_TYPE` / `_RTRef` / `_RRRef`, лишние JOIN из точечных
  путей, `?` / `p_N` вместо `&Параметр`.
- Платформенный `.СрезПоследних` в SQL обычно с физическими таблицами итогов и
  вложениями. Пара `#tt` ↔ `#tt` с self LEFT JOIN + `ЕСТЬ NULL` — чаще **ручной**
  срез в тексте запроса, не виртуальная таблица платформы.
- Context из расширения (`Prometheus …`, `ТБ_БСП …`) может указывать на модуль
  **вне** `TB/src/cf` (например `tb_ext`). Ищи модуль в workspace / соседних
  репозиториях расширений по имени из Context.

## Алгоритм

1. Извлечь `Sql`, `Context`, `client_session_id`, `Infobase`.
2. Разобрать **Context**: пропустить кадры `ДлительныеОперации`, `ОбщегоНазначения`,
   каркас `ВариантыОтчетов` до прикладного места
   (`ОбщийМодуль.…`, `Отчет.…`, `Обработка.…`, `Запрос.Выполнить` /
   `ВыполнитьПакет` / `СкомпоноватьРезультат` / `ПроцессорВывода`).
3. Определить источник текста запроса:
   - в Context есть `Отчет.<Имя>` → макет СКД
     `Reports/<Имя>/Templates/**/Template.xml`;
   - отчёт через фон / `УправлениеПоказателями` / `СформироватьОтчет*`, но **имени
     отчёта нет** → по `client_session_id` взять событие журнала регистрации
     (`1c_eventlog`): имя отчёта в `event_action_1` (или сегмент `event_action`
     вида `….ИмяОтчета.…`, события вроде «Формирование отчетов» /
     «Формирование коллекции значений» / «Выполнение отчета»);
   - иначе → модуль из Context (`Запрос.Текст`, функция текста, динамическая
     сборка пакета).
4. Подготовить якоря из `Sql` (без `EXISTS`/RLS):
   - физические `_Document*` / `_InfoRg*` / `_Reference*` / `_AccumRg*` →
     `1c-sql-translate` (или index schema) → имена метаданных;
   - только `#tt*` / `#t*` → форма шага: `UNION`/`JOIN`, ручной срез, число полей,
     булевы `0x00`/`0x01`, литералы из `p_N`.
5. В найденном модуле/макете сопоставить шаг (`ПОМЕСТИТЬ …`, ветка `ОБЪЕДИНИТЬ`,
   соединение с той же бизнес-таблицей / условием).
6. **Открыть файл** на найденной строке. В ответе: стек → путь → цитата фрагмента
   1С; при необходимости одной фразой, что раздутый SQL — RLS/типы платформы.

## Якоря матча (приоритет)

1. Context (прикладной кадр).
2. Имя отчёта из eventlog по сессии.
3. Бизнес-таблицы/поля после перевода schema.
4. Литералы в `p_N` (строки, имена метаданных).
5. Форма шага: `UNION ALL`, self-join среза, `ПОМЕСТИТЬ`, отличительные условия.

## Примеры исходов

| Ситуация | Куда смотреть |
|----------|----------------|
| Context → `…ПолучитьПакетныйЗапрос…ВыполнитьПакет` | текст пакета в общем модуле; шаг по форме SQL / `#tt` |
| Context → `Отчет.ДолжникиСОбещаниемОплат` + ручной срез `#tt` | `Template.xml`, self LEFT JOIN той же ВТ + `ЕСТЬ NULL` |
| Context без имени отчёта, user/фон показателей или `СформироватьОтчет*` | `client_session_id` → eventlog → `Reports/<event_action_1>/…` |
| Context → `Обработка.…ИтоговыйЗапрос.Выполнить` | модуль объекта; шаг по бизнес-таблицам и литералам, игнор `EXISTS` |
| Context → `Отчет.<Имя>.…СкомпоноватьРезультат` / `ПроцессорВывода` | сразу `Reports/<Имя>/…/Template.xml` |
| Context → расширение (`Prometheus_…`), файла нет в `src/cf` | модуль в репозитории расширения; шаг по `1c-sql-translate` + форме SELECT/JOIN |
| `Sql` = `success … native quick insert` | не запрос — пропустить |

## Связанные навыки

- `1c-sql-translate` — имена таблиц/полей SQL → метаданные 1С.
- Не подменяет поиск текста запроса в конфигурации.
